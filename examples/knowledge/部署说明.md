# 部署说明

## 本地开发

1. 安装依赖：`pip install -e ".[dev]"`。
2. 复制配置：`Copy-Item .env.example .env`。
3. 启动服务：`python -m tsukiyohub`，默认监听 8080 端口。
4. 打开 <http://127.0.0.1:8080/docs> 查看交互式接口文档。

## 生产部署

推荐使用 Docker Compose 部署，包含应用、PostgreSQL 与 Milvus 三个服务。

### 数据库

生产环境使用 PostgreSQL，配置项 `DATABASE_URL` 形如：

```
postgresql+psycopg://user:password@127.0.0.1:5432/tsukiyohub
```

服务启动时会自动建表，不需要手动执行迁移。

### 向量库

生产环境建议使用 Milvus：设置 `VECTOR_BACKEND=milvus`，并配置 `MILVUS_URI`，
默认地址是 `http://127.0.0.1:19530`。Milvus 连不上时服务会自动退回到内存检索后端，
此时索引只在本进程中有效，重启后需要重建索引。

### 反向代理

如果前面有 Nginx，SSE 流式接口需要关闭缓冲：

```nginx
location /api/chat/stream {
    proxy_pass http://127.0.0.1:8080;
    proxy_buffering off;
    proxy_read_timeout 300s;
    proxy_set_header Connection "";
}
```

## 环境变量

完整清单见 `.env.example`。最常用的几个：

- `LLM_API_KEY` / `LLM_MODEL` / `LLM_BASE_URL`：对话模型。
- `EMBEDDING_PROVIDER`：向量化供应商，可填 openai、dashscope 或 hash。
- `VECTOR_BACKEND`：检索后端，可填 memory 或 milvus。
- `DATABASE_URL`：留空则使用 SQLite 文件 data/tsukiyohub.db。
- `GROUNDING_MIN_SCORE`：判定「知识库里没有」的阈值，更换向量化模型后需要重新标定。
- `API_KEY`：对外接口鉴权，留空表示不鉴权。
