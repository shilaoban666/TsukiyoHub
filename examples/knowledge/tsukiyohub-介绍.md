# TsukiyoHub 是什么

TsukiyoHub 是一个与业务无关的「聊天 + 技能 + 检索增强生成（RAG）」内核服务。
它把一次对话需要的三件事抽出来做成独立服务：

1. **聊天**：多轮会话、模型工具循环、流式逐字输出、主备模型降级、回答核对。
2. **技能**：模型可以调用的能力单元，包括内置工具、SKILL.md 文档技能、外部 MCP 工具。
3. **RAG**：文档解析、切块、向量化、混合检索（向量 + BM25 + RRF 融合）、证据闸门与引用来源。

任何前端都可以接入：Web 页面、桌面应用、IDE 插件、聊天机器人、Dify / FastGPT 这类平台，
只要会发 HTTP 请求即可，也支持 OpenAI 兼容协议。

## 三条设计原则

- **零依赖可跑**：默认使用内存检索后端和 SQLite，不装 Milvus / PostgreSQL 也能启动；
  没配置模型密钥时使用演示模型，方便先把前端接上来。
- **防幻觉优先**：检索结果不够时如实说「没找到」，回答生成后逐句核对资料是否支持，
  不支持的句子会被删除。
- **内核与业务解耦**：内核不认识「员工」「部门」「钉钉」，这些都属于接入方的业务系统。

## 检索是怎么工作的

检索使用两路召回：向量召回负责语义相近，BM25 关键词召回负责专有名词和编号。
两路结果用加权 RRF 融合，再按需重排。融合之后有一道证据闸门：
如果最高向量余弦低于阈值，或者没有词面重叠，就判定知识库里没有答案。
